# OrbitEngine

Moteur de visual novel en Rust (wgpu + winit) avec son éditeur no-code (en construction). Cibles du jeu : Windows, Linux, Web (WebGL2), Android plus tard ; l'éditeur est natif (Windows et Linux). Le plan complet est dans [`docs/ROADMAP.md`](docs/ROADMAP.md), les décisions d'architecture dans [`docs/adr/`](docs/adr).

État : **éditeur de vue** (M3g) : taille, miroir X / Y et position libre des personnages, IR **v6** ; un panneau montre la scène au nœud sélectionné avec le vrai runtime et laisse glisser, redimensionner et inverser les personnages (voir « L'éditeur »)  ; jalon **M4 fait** : **export des jeux** (Windows zip, Linux tar.gz, web avec chargement paresseux ; `orbit build` / `orbit export`, panneau Export de l'éditeur, profils dans `orbit.project.ron` ; voir « Exporter son jeu » et l'[ADR 0010](docs/adr/0010-export-pak-et-templates.md)) et **MCP live** : l'éditeur ouvert expose le MCP en HTTP sur 127.0.0.1 (désactivé par défaut, jeton, panneau « Assistant IA » avec journal des actions de l'IA ; l'IA édite en direct, lance la preview et en prend des captures d'écran ; voir [docs/mcp.md](docs/mcp.md)) ; jalon **M3d terminé** (graphe de scènes éditable, positions dans un sidecar `.layout`, **les scènes ne s'enchaînent plus : on passe de l'une à l'autre par un « Saut de scène »**, IR v5 ; voir « L'éditeur ») ; jalon **M3e terminé** (bibliothèque d'assets avec import par glisser-déposer, miniatures asynchrones, validation en direct, panneau Problèmes, recherche globale ; voir « L'éditeur ») ; jalon **M3c terminé** (éditeur de scène linéaire, inspecteur de tous les types de nœuds, personnages, variables ; voir « L'éditeur ») ; jalon **M3f (serveur MCP headless) terminé** : `orbit mcp --project <dossier>` laisse une IA créer et modifier une histoire par MCP (voir [docs/mcp.md](docs/mcp.md)) ; jalon **M3b terminé** (preview intégrée : le vrai runtime joue l'histoire ouverte dans un panneau de l'éditeur, avec rechargement à chaud depuis la mémoire et « jouer depuis ici ») après le **M3a** (socle de l'éditeur : fenêtre egui sur le device wgpu partagé, outils intégrés sous forme de plugins, palette de commandes, projets, undo / redo, sauvegarde atomique, récupération après crash, rendu à la demande) et le **M2** (fonctionnalités VN de base : menu principal, pause, rollback, skip/auto, historique, saves multi-slots avec miniatures et autosave, préférences, i18n, variables persistantes). Le player joue une histoire RON (fond, personnages, choix, musique, transitions) en natif et dans le navigateur, avec rechargement à chaud en natif. Prochain jalon : M3d (graphe de scènes ; architecture dans l'[ADR 0009](docs/adr/0009-architecture-editeur.md)).

## Structure

| Chemin | Rôle |
|---|---|
| `crates/orbit_core` | IR de l'histoire (schéma v6 : IDs ULID, `Value`, RON, validation, migrations ; personnages avec échelle, miroir et position libre). Sans GPU, compile en wasm. |
| `crates/orbit_project` | API de commandes unique (undo/redo, transactions, événements, versions par nœud), opérations composées (`ops`) et graphe de l'histoire (`graph` : blocs et arêtes, `graph_ops` : édition, `graph_layout` : sidecar `.layout` et disposition automatique). Sans GPU. |
| `crates/orbit_vm` | VM de l'histoire : `step()` pur et non bloquant, événements de présentation, état de scène déclaratif, snapshots, rollback / roll-forward, backlog, variables persistantes, recherche de chemin bornée vers un nœud (`seek`, pour « jouer depuis ici »). Sans GPU/audio, compile en wasm. |
| `crates/orbit_save` | Saves (format versionné `postcard`, version 2 ; la 1 reste lisible, compatibilité après édition de l'histoire), slots manuels / autosaves en rotation / quicksave, données persistantes et préférences (RON), stockage fichiers (natif) ou `localStorage` (web). Sans GPU, compile en wasm. |
| `crates/orbit_i18n` | Localisation : traductions RON par `StringId`, repli sur la langue source, couverture. Sans GPU, compile en wasm. |
| `crates/orbit_plugin_api` | API de plugins, côté projet : manifeste, types de nœuds personnalisés, validateurs, importeurs, outils MCP, hooks d'événements, `API_VERSION`. Sans GPU ni egui, compile en wasm (contrôlée par `check-arch`). |
| `crates/orbit_editor_api` | API de plugins, côté éditeur (egui) : `EditorPlugin`, `EditorContext` (lecture du projet, commandes seulement, sélection), registres de panneaux, actions (palette, menus, raccourcis) et inspecteurs. |
| `crates/orbit_editor` | L'éditeur (binaire `orbit-editor`, natif) : `EditorCore` (sans GPU, testé en headless), dock `egui_dock`, thème maison clair / sombre, palette de commandes, projets, récupération, les outils intégrés qui sont tous des plugins, `PreviewHost` (le runtime embarqué, sa render target enregistrée dans egui), import d'assets (`assets`), miniatures (`thumbs`), surveillance de fichiers (`watch`), validation en direct (`diagnostics`) et recherche globale (`search`). Jamais lié au player. |
| `vendor/` | `egui-snarl` 0.12.0 et `egui-scale` 0.6.1, sources inchangées (seul le `Cargo.toml` diffère : `egui` sans features par défaut, pour ne pas tirer des polices hors de `deny.toml`), voir `vendor/egui-snarl/VENDORED.md`. |
| `crates/orbit_pak` | Fichiers du jeu, sans I/O, compile en wasm : le **pak** (conteneur versionné index + données, LZ4 optionnel, CRC-32, queue pour l'accoler à un exécutable) et le **pack de jeu** (histoire + traductions + identité en postcard). |
| `crates/orbit_export` | Export des jeux (sans egui) : compile un projet (validation bloquante, assets utilisés), construit le pak, produit le zip Windows, le tar.gz Linux et le bundle web (page + loader, brotli / gzip) à partir des templates de player ; serveur de test local. Utilisé par le CLI, l'éditeur et le MCP. |
| `crates/orbit_cli` | Binaire `orbit` : `validate`, `run-text` (jeu en terminal), `build`, `export <windows\|linux\|web\|all>`, `mcp` (serveur MCP headless, voir [docs/mcp.md](docs/mcp.md)). |
| `crates/orbit_mcp` | Serveur MCP (SDK `rmcp`) : headless (stdio, sans GPU) ou **live** (HTTP sur 127.0.0.1 dans l'éditeur, jeton, file de commandes vers le fil de l'éditeur) ; une IA lit et modifie un projet par les commandes d'`orbit_project` (outils, ressources, schéma de l'IR, journal, périmètre limité au dossier du projet, verrou `.orbit/lock`). Jamais dans le player (`check-arch`). |
| `crates/orbit_platform` | Fenêtre et boucle d'application (winit), natif et web ; requêtes à l'hôte (plein écran, quitter), horloge, fuseau et langue du système. |
| `crates/orbit_gfx` | Couche wgpu : surface, textures RGBA8, pipeline de sprites (WebGL2 inclus). |
| `crates/orbit_render2d` | Renderer 2D : sprites batchés, calques, caméra virtuelle 1920x1080 + letterbox, render targets (rendu dans une cible, y compris les transitions), relecture asynchrone d'une render target (miniatures, capture de la preview). |
| `crates/orbit_text` | Texte (`cosmic-text`) : atlas de glyphes, machine à écrire, balises `{color=}`, `{b}`, `{i}`, `{w=}`. |
| `crates/orbit_audio` | Audio (`kira`) : musique avec boucle et fade, effets, bus de volume, déblocage par geste utilisateur. |
| `crates/orbit_assets` | Chargement asynchrone (threads en natif, `fetch` sur le web), décodage PNG/WAV/OGG, surveillance de fichier (hot reload), lecture d'un pak (fichier natif ; requêtes HTTP `Range` sur le web). |
| `crates/orbit_ui` | UI en jeu data-driven (`Theme` RON) : textbox, choix, widgets, écrans (menu principal, pause, sauvegarde/chargement, préférences, historique, quick menu, toasts), textes d'interface en/fr. |
| `crates/orbit_runtime` | Runtime : orchestre VM, assets, rendu, texte, audio et UI. `Shell` = machine d'état sans GPU (écrans, saves, autosave, préférences, langue, persistants), `Game` = skip/auto, `Director` = VM + rollback, `Runtime` = GPU, audio, miniatures ; en mode « embarqué » (`Runtime::new_embedded`) il charge une `Story` depuis la mémoire, joue dans une render target et se recharge à chaud (module `preview` : points de départ et reprise, sans GPU ; module `scene_view` : la scène à un nœud, pour l'éditeur de vue ; `Runtime::render_stage_to_target` dessine une scène fixe avec le code du jeu). Indépendant du binaire. |
| `crates/orbit_player` | Binaire du jeu (natif et wasm) : lit les arguments / l'URL et lance `orbit_runtime`. Joue aussi un jeu exporté (pak accolé à l'exécutable, `game.pak`, `--pak`, `ORBIT_PAK` côté web). Contient la démo visuelle codée en dur (`--demo`) et la galerie des écrans d'UI (`--ui-gallery`), feature `showcase`, absente des templates. |
| `xtask` | Automatisation : `web`, `serve`, `templates` (players précompilés de l'export), `wasm-budget`, `check-arch`, `gen-assets`. |
| `tools/make_ui_fonts.py` | Génère les copies d'Inter de l'éditeur (`assets/fonts/ui/`) sans les glyphes d'usage privé qui masquent les icônes Phosphor. |
| `examples/stories/demo.ron` | Histoire d'exemple ; `examples/stories/i18n/` : sa traduction française et `index.txt` (liste des traductions). |
| `assets/demo/`, `assets/fonts/` | Assets de la démo (générés par `cargo xtask gen-assets`) et police Inter (OFL). |

## Commandes

Prérequis : Rust via `rustup` (la toolchain 1.95 et la cible wasm sont installées par `rust-toolchain.toml`). Linux : les bibliothèques de développement X11 / Wayland / xkbcommon / Vulkan (voir `.github/workflows/ci.yml`).

```sh
cargo run -p orbit_editor                               # l'éditeur (accueil, projets récents)
cargo run -p orbit_editor -- examples/stories/demo.ron  # ouvre l'histoire de démo (ou un dossier de projet)
cargo run -p orbit_player          # joue examples/stories/demo.ron (natif)
cargo run -p orbit_player -- ma/story.ron --root ma/    # une autre histoire
cargo run -p orbit_player -- --new-game                 # sans menu principal, nouvelle partie directe
cargo run -p orbit_player -- --data-dir saves/          # saves et préférences dans un dossier choisi
cargo run -p orbit_player -- --demo                     # démo visuelle codée en dur
cargo run -p orbit_player -- --ui-gallery               # tous les écrans d'UI, données factices
cargo run -p orbit_cli -- validate examples/stories/demo.ron --check-files
cargo test --workspace             # tests
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo deny check                   # licences, bans, sources, advisories

# Web
cargo install wasm-bindgen-cli --version 0.2.129 --locked   # doit égaler la version de Cargo.lock
cargo xtask web                    # build wasm32 release + bundle (assets, polices, histoires d'exemple) dans target/web/
cargo xtask serve                  # http://127.0.0.1:8080 (Ctrl+C pour arrêter) ; --port <n> pour un autre port
# puis ouvrir / (démo M1), /?story=examples/stories/demo.ron ou /?demo (démo visuelle)

# Export des jeux (voir « Exporter son jeu »)
cargo xtask templates              # players précompilés dans target/templates (wasm-opt si installé : cargo install wasm-opt --locked)
cargo xtask wasm-budget            # échoue si le player web dépasse le budget de taille
cargo run -p orbit_cli -- export web --project mon_jeu --out dist --serve

# Architecture : core/project sans GPU ni fenêtre, compilables en wasm
cargo xtask check-arch
```

## L'éditeur

`cargo run -p orbit_editor [-- <projet | histoire.ron>]` (ajoutez `--release` pour la vitesse ; `orbit-editor --help` liste les options).

* **Projet** : un dossier avec `orbit.project.ron` (nom, fichier d'histoire, plugins requis), `story.ron` (l'histoire, RON canonique, lisible par le player et `orbit validate`), `assets/` et `.orbit/` (état d'outil : récupération après crash, ignoré par git). Fichier > Nouveau projet crée un projet minimal ; Fichier > Ouvrir un projet / une histoire (`.ron` seul, sans dossier de projet) utilise le sélecteur de fichiers natif ; la page d'accueil liste les projets récents.
* **Interface** : dock (explorateur à gauche, accueil au centre, inspecteur à droite, console en bas ; onglets déplaçables, disposition conservée dans `%APPDATA%\OrbitEngine\Editor` ou `~/.config/orbit-engine/editor`), thème sombre ou clair (Affichage), menus et **palette de commandes** (Ctrl+K ou Ctrl+Maj+P : recherche floue, raccourcis affichés ; Affichage > « Afficher : … » rouvre un panneau fermé).
* **Édition (M3a)** : sélectionner une réplique dans l'explorateur, modifier son texte et son personnage dans l'inspecteur, ajouter (Ctrl+Entrée) ou supprimer (Suppr) une réplique ; l'éditeur de scène complet est M3c. Tout passe par les commandes d'`orbit_project` : Ctrl+Z / Ctrl+Y (ou Ctrl+Maj+Z) annulent et rétablissent (une saisie de texte = une étape), Ctrl+S enregistre de façon atomique, le titre et la barre d'état signalent les modifications non enregistrées, la fermeture demande confirmation. Un enregistrement automatique de secours est écrit toutes les 30 s tant que le projet est modifié ; après un arrêt brutal, le lancement suivant propose de restaurer.
* **Éditeur de scène (M3c)** : le panneau Scène (au centre) liste les lignes de la scène courante (répliques avec avatar et couleur du personnage, choix avec leurs options, décors, sprites, musiques, variables, conditions, étiquettes, plugins), virtualisée (5000 nœuds fluides). Clic sur une réplique sélectionnée ou Entrée : édition en place (Entrée = nouvelle réplique, Maj+Entrée = retour à la ligne, Échap = terminer, Retour arrière sur une ligne vide = la supprimer) ; le nom du locuteur ouvre un menu. **Ctrl+Entrée** ajoute une réplique, **Ctrl+I** ouvre le menu rapide de tous les types (le « Choix » crée ses deux branches et leur étiquette de suite), « Ajouter » liste tous les types. Maj / Ctrl+clic pour la multi-sélection, **glisser-déposer** (poignée) ou **Alt+↑ / Alt+↓** pour réordonner, Ctrl+D / C / X / V (dupliquer, copier, couper, coller avec de nouveaux identifiants), Suppr, Ctrl+A ; menu contextuel par ligne ; scènes : créer, renommer (F2), réordonner, supprimer. Chaque geste est une seule étape d'annulation. Les points rouge / orange signalent les erreurs et avertissements de validation. L'**inspecteur** édite tous les types de nœuds (champs typés : personnage, expression avec aperçu, position, ressource filtrée par type avec ajout de fichier, transition, condition avec éditeur simple ou expression analysée avec erreur en ligne, cibles de saut parmi les étiquettes, données génériques des nœuds de plugin). Panneaux **Personnages** (nom, couleur, position par défaut, expressions avec miniature, positions de scène ; renommer une expression met à jour les affichages) et **Variables** (type, valeur initiale, portée, renommage qui met à jour les usages ou refus avec message). Options de debug : `--generate-story <n> <fichier.ron>` (histoire de test), `--autoscroll <px>` (+ `--exit-after`, journalise le temps de frame), `--run-action orbit.scene.edit_line`.
* **Graphe (M3d)** : le panneau Graphe (onglet à côté de Scène ; menu Affichage, palette « Graphe : ... ») montre l'histoire en **blocs** (la tête de chaque scène et chaque étiquette) reliés par leurs sauts, choix (une sortie par option, avec son texte), conditions (vrai / sinon), appels et **sauts de scène**. Couleur et icône par type (scène, étiquette, choix, condition, fin, retour, appel), résumé du bloc (répliques, personnages, première réplique), pastille de validation, blocs orphelins signalés, « fin de partie » quand une scène se termine sans saut. **Une scène ne se poursuit jamais dans la suivante** : on passe de l'une à l'autre par un nœud « Saut de scène » (ajout par le menu des lignes, ou en tirant un lien depuis un bloc vers une autre scène). Édition directement dans le graphe (une étape d'annulation par geste) : *Nouvelle scène*, tirer une broche vers un bloc pour relier ou rediriger, la lâcher dans le vide pour créer une scène liée, clic droit sur un bloc (ouvrir, jouer depuis ici, ajouter un choix à deux branches ou une condition, terminer la partie, renommer, supprimer avec confirmation s'il y a des liens ou des répliques), clic droit sur une option (texte, ajouter une option, supprimer le lien) ; double-clic ouvre le bloc dans l'éditeur de scène ; la sélection est partagée avec l'explorateur, l'inspecteur et la preview. Pan en glissant le fond ou à la molette, zoom avec Ctrl + molette (ou pincement), **F** recadre, mini-carte cliquable, recherche d'un bloc, « Réorganiser » (disposition en couches). Les positions sont dans `story.layout` à côté de `story.ron` (hors de l'histoire ; écrit seulement après un déplacement). 200 blocs : ~4 ms de CPU par frame en pan / zoom continus (release). Options de debug : `--generate-graph <n> <fichier.ron>` (histoire de test de ~n blocs), `--autoscroll <px>` (fait aussi défiler le graphe), `--run-action orbit.graph.add_choice` / `orbit.graph.focus`.
* **Assistant IA (MCP live, M4)** : le panneau « Assistant IA » (zone du bas) active le serveur MCP de l'éditeur (HTTP sur `127.0.0.1`, **désactivé par défaut**, port configurable, **jeton** masqué / copiable / régénérable, boutons « Commande Claude Code » et « .mcp.json » prêts à coller). L'IA modifie le projet ouvert **en direct** (une entrée d'annulation par appel, versions de nœud contre les conflits avec vos propres modifications), lance la preview, avance dans l'histoire, lit son état et en prend une **capture d'écran** (contenu image MCP). Le panneau liste en direct ce qu'elle fait (outil, arguments, résultat, durée, « révéler » le nœud touché) et propose « Annuler la dernière action de l'IA ». Un verrou `.orbit/lock` évite d'ouvrir le même projet dans l'éditeur et dans `orbit mcp` sans avertissement. Détails, configuration et sécurité : [docs/mcp.md](docs/mcp.md). Options de debug : `--mcp-port <port>`, `--mcp-token <jeton>`.
* **Preview (M3b)** : le panneau Preview (en haut à droite par défaut ; menu Preview, palette) joue le **vrai runtime** dans une texture d'egui sur le même device wgpu, au format 16:9. Barre d'outils : lecture / pause (F6), arrêt (Maj+F6), recommencer (Ctrl+F6), **jouer depuis ici** (F7, bouton « Ici », ou la cible sur la ligne sélectionnée / le menu contextuel de l'explorateur : l'état réel au nœud — décor, personnages, musique, variables — est reconstitué par une recherche de chemin bornée dans les choix ; si aucun chemin n'existe, repli sur l'état par défaut avec un avertissement dans la console), vitesse 1× / 2× / saut (s'arrête aux choix), son coupé, suivi de la lecture dans l'explorateur, plein panneau. Cliquez dans l'image pour lui donner le focus : alors seulement la souris et le clavier (Entrée, Espace, flèches, 1-9, Échap, H, S, A, F5, F9, Ctrl) vont au jeu ; un clic ailleurs rend le clavier à l'éditeur. **Chaque modification de l'histoire** (frappe, annulation, ajout) recharge la preview depuis l'état mémoire (environ 100 ms de délai anti-rebond, puis < 5 ms) et reprend au même nœud ; si le nœud a disparu, au label le plus proche avant lui, sinon au début ; une histoire invalide n'est pas jouée (la dernière version valide continue, l'erreur est lisible dans le panneau). Les saves de la preview restent en mémoire. La preview ne dessine que pendant la lecture active (frappe du texte, transitions, pauses, saut) : en pause, arrêtée, masquée, fenêtre en arrière-plan ou jeu qui attend un clic, **0 frame**. Options de debug : `--play-preview`, `--preview-skip`, `--play-from-selection` (avec `--select-node`), `--edit-text <n>=<texte>` (simule une frappe), `--preview-capture <png>` (relecture de la cible, 16:9), `--always-active` (ignore la perte de focus de la fenêtre).
* **Éditeur de vue (M3g)** : le panneau « Éditeur de vue » (onglet à côté de Scène et Graphe ; Affichage > Afficher : Éditeur de vue) montre **la scène telle qu'elle est au nœud sélectionné** : décor, personnages, positions, échelles et miroirs, dessinés par le vrai runtime dans une texture d'egui (même recherche de chemin que « jouer depuis ici », puis le nœud est exécuté). Sélectionnez un nœud « Afficher » : son personnage est cadré avec ses poignées. **Glissez-le** pour le placer librement (le `Show` devient une position libre `Free(x, y)`, mise à jour en direct, la preview suit ; **une seule entrée d'annulation par glisser**, Échap annule le geste) ; les **poignées** changent l'échelle autour des pieds (Maj : garder le ratio ; un côté étire un seul axe) ; **Miroir X / Miroir Y** ; **Magnétisme** sur gauche / centre / droite et les positions du projet (Alt : désactiver pendant le glisser) et **Grille** de 5 % ; **Repères** (gauche / centre / droite, positions personnalisées, marges de sécurité 16:9) ; **flèches** pour un déplacement fin (Maj : grand pas) ; un clic sur un autre personnage sélectionne le « Afficher » qui l'a placé. L'inspecteur d'un « Afficher » règle la même chose avec des champs : position (gauche / centre / droite / positions du projet / **Libre** avec X et Y), échelle (curseur, étirement vertical optionnel, retour à l'échelle du personnage), miroir X / Y ; le panneau Personnages donne l'**échelle par défaut** de chaque personnage. Un « Afficher » sur un personnage déjà présent met à jour sa position, son échelle et son miroir. Rien à redessiner au repos (0 frame). Les mêmes réglages sont disponibles par MCP (`scale`, `flip_x`, `flip_y`, position `{x, y}`, `default_scale`). Options de debug : `--select-node <n>` et `--run-action orbit.core.views.show.orbit.sceneview.sceneview` (ouvre le panneau) avec `--screenshot`.
* **Plugins** : chaque outil (explorateur, inspecteur, console, accueil, preview, éditeur de vue) est un `EditorPlugin` ; le « Plugin d'essai » (Affichage > Afficher : Plugin d'essai, ou Outils) montre un panneau, des actions et un type de nœud ajoutés par l'API publique.
* **Assets, validation en direct, recherche (M3e)** :
  * **Bibliothèque d'assets** (panneau « Assets », en bas) : grille ou liste de toutes les images, musiques et sons du projet, filtres par type, recherche, tri (nom, type, taille), miniatures (décodées hors du fil d'interface, cache disque `.orbit/thumbs/`, chargées seulement pour les lignes visibles), durée des sons, **écoute** (lecture / arrêt, double-clic). **Import** : bouton « Importer » (Ctrl+Maj+I) ou **fichiers et dossiers déposés sur la fenêtre** depuis l'explorateur du système : chaque fichier est validé par décodage (un faux PNG, un WAV tronqué, un format inconnu sont refusés avec la raison), copié sous `assets/images/`, `assets/music/` ou `assets/sounds/` avec un nom sûr et unique (sans collision, même de casse), déclaré au manifeste sous un `AssetId` stable ; le tout est **une seule étape d'annulation**. Glisser une vignette sur un champ ressource de l'inspecteur ou sur une ligne Décor / Musique / Son de l'éditeur de scène l'assigne. **Renommer** un fichier garde son identifiant (donc toutes les références ; annuler remet aussi le fichier en place) ; **retirer** une ressource est refusé tant qu'un nœud **ou une expression de personnage** l'utilise (le fichier reste sur le disque). Les fichiers de `assets/` absents du manifeste apparaissent marqués « non déclaré » (menu contextuel : « Déclarer »).
  * **Surveillance de fichiers** : un fil d'arrière-plan compare toutes les 500 ms l'histoire et le dossier `assets/` ; un asset ajouté, remplacé ou supprimé rafraîchit miniatures, problèmes et preview ; une histoire modifiée hors de l'éditeur propose de la **recharger** (avec un avertissement de conflit si le projet a aussi des modifications non enregistrées ; l'enregistrement de l'éditeur lui-même n'est pas signalé).
  * **Validation en direct** : les erreurs et avertissements sont recalculés à chaque modification (immédiatement pour une petite histoire ; au-delà de 1500 nœuds, une première modification est validée aussitôt et une rafale est limitée à une validation toutes les 80 ms, sur un fil d'arrière-plan : la frame n'attend jamais). Panneau **Problèmes** (icône, message, emplacement ; le clic sélectionne et révèle le nœud dans l'explorateur, l'éditeur de scène et l'inspecteur, ou ouvre le personnage / la variable / l'asset ; F8 = problème suivant) et pastilles d'erreurs / avertissements dans la barre d'état. Contrôles : références, ressources manquantes (**fichier introuvable, écart de casse** entre manifeste et disque, qui casse sous Linux et sur le web), plugins absents, validateurs de plugins.
  * **Recherche globale** (**Ctrl+Maj+F**) : répliques, choix, personnages, variables, étiquettes, scènes, assets ; résultats groupés par type avec les mots trouvés en gras, flèches et Entrée, clic pour révéler. La **palette** (Ctrl+K) ajoute la navigation (scènes, personnages, assets, répliques) aux commandes.
  * Options de debug : `--import <fichier|dossier>` (comme un dépôt, répétable), `--search <texte>`, `--select-asset <n>`, `--run-action orbit.core.views.show.orbit.library.library` (ou `…problems.problems`, `…search.search`).
* **Langue de l'interface (anglais / français)** : tous les textes de l'éditeur (menus, panneaux, palette, infobulles, messages, problèmes de validation, dialogues) existent en **anglais** et en **français**. Au premier lancement l'éditeur prend la langue du système (français pour `fr*`, anglais sinon) ; **Affichage > Langue** (ou la palette : « Langue : English » / « Langue : Français ») change la langue **à chaud**, sans redémarrage, et le choix est conservé dans la config utilisateur. `--lang en|fr` force la langue pour une exécution sans l'enregistrer (captures d'écran). Les textes sont des tables RON embarquées (`crates/orbit_editor/locales/<langue>/*.ron`) ; un plugin enregistre ses propres tables avec `EditorRegistry::texts` (voir l'ADR 0009, notes i18n).
* **Performance** : l'éditeur ne dessine une frame que sur événement ou échéance (0 frame au repos). `--frame-counter` journalise chaque frame, `--screenshot <png> --exit-after <s>` enregistre la frame rendue (utile aux tests visuels : `--open-palette`, `--theme light`, `--select-node <n>`, `--run-action <id>`).

## Jouer une histoire

* **Écrans** : « Cliquer pour démarrer » (web uniquement : débloque l'audio, obligatoire dans les navigateurs ; en natif le jeu démarre directement sur les splashs) puis menu principal (Nouvelle partie, Continuer = la save la plus récente, Charger, Préférences, Quitter en natif). En jeu, Échap ou clic droit ouvre la pause (Reprendre, Sauvegarder, Charger, Historique, Préférences, Menu principal) ; Échap / clic droit ferme l'écran ouvert. À la fin de l'histoire, un clic revient au menu principal.
* **Avancer** : clic, Espace ou Entrée (le premier appui complète la machine à écrire, le suivant passe à la réplique ; pendant une transition, il la termine). Choix : survol et clic, flèches haut/bas + Entrée, ou touches 1 à 9. Les clics sur le quick menu (Retour, Historique, Saut, Auto, Q.Save, Q.Load, Préf., Menu) n'avancent pas le dialogue.
* **Rollback** : molette vers le haut, flèche gauche, Page précédente ou bouton « Retour » reviennent d'une réplique (scène, personnages et musique sont restaurés sans transition) ; molette vers le bas, flèche droite ou Page suivante avancent dans l'historique conservé. « Revenir ici » dans l'historique (touche H) saute à une réplique précise.
* **Skip / Auto** : Ctrl maintenu = saut temporaire ; bouton ou touche S = bascule ; bouton ou touche A = mode auto. Le saut s'arrête aux choix et, en mode « texte lu uniquement » (préférence), aux répliques non lues ; l'auto attend la fin de la frappe puis un délai proportionnel à la longueur. Toute action du joueur coupe skip et auto.
* **Saves** : F5 sauvegarde rapide, F9 chargement rapide, écrans Sauvegarder / Charger (emplacements manuels, autosaves, sauvegarde rapide ; miniature, date, scène, dernière réplique). Autosave au début de chaque scène et toutes les 20 répliques, plus une dernière autosave à la fermeture de la fenêtre. Une save devenue incompatible est grisée ; une save endommagée donne une notification, jamais un crash. Emplacement : natif `%APPDATA%\OrbitEngine\<jeu>` (Windows), `~/Library/Application Support/OrbitEngine/<jeu>` (macOS), `$XDG_DATA_HOME` ou `~/.local/share/OrbitEngine/<jeu>` (Linux), ou `--data-dir` ; web : `localStorage` (clés `orbit/<jeu>/...`, environ 5 Mo par origine).
* **Préférences** (écran dédié, enregistrées à chaque changement) : volumes des bus, vitesse du texte, délai auto, mode skip, plein écran (natif ; F11 ou Alt+Entrée), langue.
* **Langues** : le player charge les traductions listées dans `i18n/index.txt` à côté de l'histoire (fichiers `<histoire>.<langue>.ron`, voir `examples/stories/i18n/`) ; sans préférence, la langue du système ou du navigateur est utilisée si elle est disponible, sinon la langue source. Changement à chaud : la réplique affichée est traduite sur place.
* **Natif** : `orbit_player [histoire.ron | dossier-projet] [--root <dossier>] [--no-watch] [--new-game] [--data-dir <dossier>]`. La racine des assets (chemins du manifest) est `--root`, sinon le dossier du projet, sinon le dossier courant (comme `orbit validate --check-files`) ; la démo par défaut utilise la racine du dépôt.
* **Hot reload** (natif) : si le fichier RON change sur disque, il est rechargé, revalidé et l'histoire redémarre du début ; une erreur s'affiche à l'écran jusqu'à correction.
* **Web** : `?story=<chemin>` relatif à la page (le bundle contient `examples/stories/` et `assets/`) ; `?new-game` démarre directement une partie après le clic initial.

`RUST_LOG=debug cargo run -p orbit_player` règle le niveau de logs natif ; sur le web les logs vont dans la console du navigateur.

## Exporter son jeu

Un projet (`orbit.project.ron`, `story.ron`, `assets/`, `i18n/`) devient un jeu qu'on distribue sans rien installer :

```sh
orbit build  --project mon_jeu                       # valide, compile, écrit build/<id>.pak
orbit export windows --project mon_jeu --out dist    # zip : <Jeu>/<Jeu>.exe
orbit export linux   --project mon_jeu --out dist    # tar.gz : <Jeu>/<id>
orbit export web     --project mon_jeu --out dist --serve   # dossier pour un hébergeur statique, et test local
```

* **Compilation** : les erreurs de validation et les assets utilisés manquants **bloquent** ; les assets déclarés mais inutilisés, les traductions incomplètes, etc. sont des avertissements. Seuls les assets utilisés sont exportés (pak versionné, LZ4 optionnel).
* **Templates** : l'export colle le pak à un player précompilé (`cargo xtask templates`, ou le dossier `templates/` livré avec l'éditeur ; ordre de recherche et configuration dans [docs/premiers-pas.md](docs/premiers-pas.md)). Le template Linux vient de la CI.
* **Web** : `wasm-bindgen` + `wasm-opt`, page avec loader et vraie barre de progression, fichiers `.br` / `.gz`, chargement paresseux du pak par requêtes `Range` (scène affichée + scènes suivantes préchargées). Player ~4,4 Mo (10,2 Mo avant), ~1,4 Mo en brotli ; budget vérifié en CI.
* **Éditeur** : Fichier > Exporter le jeu… (profils, cibles, progression, journal, ouvrir le dossier, tester dans le navigateur). L'IA connectée en MCP live dispose de `build_project` / `export_game`.
* Limites : l'icône du fichier `.exe` reste celle d'OrbitEngine (celle de la fenêtre est celle du jeu) ; pas de macOS ni de signature de code ; sauvegardes web en `localStorage` (décision dans l'ADR 0010).

## Installer l'éditeur

Les installeurs sont produits par `cargo-packager` (CI : job `release`, attaché à une GitHub Release en brouillon) :

* **Windows** : `orbit-editor_<version>_x64-setup.exe` (NSIS, installation par utilisateur ou pour tous, `/S` pour le mode silencieux) et `orbit-editor_<version>_x64_en-US.msi` (WiX, par machine). Raccourcis Menu Démarrer (et Bureau), entrée « Applications et fonctionnalités » pour désinstaller, icône de l'éditeur.
* **Linux** : `.AppImage` (portable : `chmod +x` puis lancer) et `.deb` (`sudo apt install ./orbit-editor_<version>_amd64.deb`, fichier `.desktop` et icônes inclus).
* **Contenu** : l'exécutable, le projet démo (`examples/stories/`, `assets/demo/`) et un dossier `templates/` à côté de l'exécutable (les templates de player de l'export de jeux, produits par la CI). Les polices et le logo sont dans l'exécutable. Version = celle du workspace, affichée dans la barre d'état (en bas à droite).
* **Construire soi-même** : `cargo install cargo-packager --locked`, `cargo build --release -p orbit_editor`, puis dans `crates/orbit_editor` : `cargo packager --release --formats wix,nsis` (Windows) ou `--formats appimage,deb` (Linux). Sortie dans `target/packager/`. WiX et NSIS sont téléchargés automatiquement.
* Pas d'auto-update ni de signature de code pour l'instant (Windows affichera SmartScreen). Une archive portable (zip / tar.gz) reste produite par la CI.
